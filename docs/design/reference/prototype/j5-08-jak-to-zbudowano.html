Architektura

  1. Przeglądarka
  2. API
  3. Baza danych

Przeglądarka dostaje gotowy HTML, a API zapisuje każdą odpowiedź od razu, więc przerwana sesja niczego nie traci. Konkretny stack opiszemy po etapie architektury.

Proces i decyzje

Warsztaty z właścicielem: wizja, 5 podróży użytkownika, 22 story z kryteriami akceptacji i 8 kroków designu. Każda decyzja ma autora w rejestrze decyzji, a decyzje techniczne mają ADR-y.

Jakość

Pokrycie testami co najmniej 95% w każdej części, testy E2E na ekranie 320 px i kontrola dostępności narzędziem axe. CI blokuje scalenie, gdy coś nie przechodzi.

Bezpieczeństwo i prywatność

Hasła tylko jako skrót, limity prób logowania i rejestracji, ścisła polityka CSP bez skryptów w treści strony. Fonty z własnego serwera, bez trackerów. Model językowy działa tylko przy imporcie słówek, nigdy po kliknięciu użytkownika.
